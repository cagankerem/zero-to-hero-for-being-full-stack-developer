"Phase 0/Phase 0.1/process observing example/os-lab.mjs" dosyasının içeriğindeki kodların işlevi: 
    - Node ve dosyan: disk
    - Çalışan node örneği: process
    - Buffer nesneleri ve runtime verileri: bellek
    - /cpu hesaplaması: CPU
    - Node runtime’ın kullandığı yürütme akışları: thread
    - HTTP sunucusu: socket ve port
    - os-lab-output.log: açık ve yazılan dosya

Örnek Process'i başlatmak: 
    Birinci terminalde:
        "node os-lab.mjs" komutunu çalıştır;
    Şuna benzer bir çıktı alacaksın:
        PID: 12345
        Port: 127.0.0.1:3000
        Başlangıç RSS: 42.3 MiB
    Gerçek PID’yi sonraki cli komutlarında kullan (shell variable ataması):
        LAB_PID=12345
    "node os-lab.mjs" komutunun sonucunda çıkan PID: 12345 olduğu varsayıldığında:
        PID: 12345
    şunu çalıştırırsın:
        LAB_PID=12345
    Sonrasında:
        ps -p "$LAB_PID"
    shell tarafından şu komuta dönüştürülür:
        ps -p 12345
    Maksat PID’yi her komutta tekrar yazmamak ve yanlış process’i inceleme riskini azaltmaktır:
        ps -p "$LAB_PID"
        lsof -p "$LAB_PID"
        top -l 1 -pid "$LAB_PID"
    Atamayı doğrulamak için:
        printf '%s\n' "$LAB_PID"

Process, bellek ve thread’leri incele:
    Aynı terminalde:
        ps -o pid,ppid,state,%cpu,%mem,rss,vsz,etime,command -p "$LAB_PID"
    Örnek Çıktı:
        PID  PPID STAT  %CPU %MEM   RSS      VSZ         ELAPSED   COMMAND
          4610 2421 S+    0.0  0.1    11264    446292928   14:21     node os-lab.mjs
    Önemli sütunlar:
        - PID: process kimliği
        - PPID: process’i başlatan parent process
        - STATE: process durumu
        - %CPU: kullanılan CPU miktarı
        - RSS: gerçekten RAM’de bulunan yaklaşık bellek, KiB
        - VSZ: ayrılmış sanal adres alanı; gerçek RAM kullanımı değildir
        - ETIME: process’in ne kadar süredir çalıştığı

    Thread sayısını görmek için:
        "top -l 1 -pid "$LAB_PID" \

    Birden fazla thread görmen, JavaScript kodunun otomatik olarak bütün thread’lerde çalıştığı anlamına gelmez. 
    Node runtime’ı yardımcı işler için ek thread’ler kullanabilir; JavaScript callback’lerimiz burada ağırlıklı olarak ana JavaScript thread’inde çalışır.
            
            **Meraklısına: 
        Programlama dili ile thread aynı kavram değildir.
        Node.js, JavaScript kodunu çalıştırmak ve işletim sistemiyle iletişim kurmak için C/C++ ile geliştirilmiş runtime bileşenleri kullanır. Bu runtime, bazı işleri yardımcı thread’lere aktarır; fakat native kod kullanılması tek başına yeni thread oluşturulduğu anlamına gelmez.

        Node.js’in kendisi büyük ölçüde C/C++ ile geliştirilmiş bileşenlerden oluşur:
        - V8 JavaScript motoru: çoğunlukla C++
        - libuv: çoğunlukla C
        - OpenSSL gibi bazı bağımlılıklar: C/C++
        - Node’un native binding’leri: C/C++
            Fakat CPU çalışırken “JavaScript” veya “C++” çalıştırmaz; bunlardan üretilmiş makine komutlarını yürütür.
            Ek thread’lerin asıl nedeni, Node runtime’ının bazı işleri paralel veya arka planda yürütmeye ihtiyaç duymasıdır:
        - V8’in garbage collection ve JIT compilation gibi yardımcı işleri
        - libuv worker pool üzerinden dosya sistemi işlemleri
        - Bazı DNS işlemleri
        - Bazı kriptografi ve sıkıştırma işlemleri
        - Runtime’ın kendi bakım ve gözlem işleri
            
Dinlenen portu görüntüle:
        "lsof -nP -a -p "$LAB_PID" -iTCP:3000 -sTCP:LISTEN"
    Örnek Çıktı:
        COMMAND  PID  USER   FD   TYPE       DEVICE SIZE/OFF     NODE NAME
        node     4610 cagan  18u  IPv4       0x3591937d4645d119  0t0  TCP 127.0.0.1:3000 (LISTEN)

    Açık tuttuğumuz log dosyasını bul:
        "lsof -p "$LAB_PID" | grep -F "os-lab-output.log""
    Örnek Çıktı:
        node 4610 cagan 17w REG 1,18 74 45684294 /Users/cagan/Documents/zero-to-hero/Phase 0/Phase 0.1/process observing example/os-lab-output.log

Normal HTTP isteğini gözlemle:
    "curl -i http://127.0.0.1:3000/"
    Örnek Çıktı:
        HTTP/1.1 200 OK
        Date: Wed, 26 Aug 2026 16:48:52 GMT
        Connection: keep-alive
        Keep-Alive: timeout=5
        Content-Length: 32
    Ardından:
        "tail os-lab-output.log" -> çalıştıramadım?
    Akış şöyledir:
    curl
     → TCP bağlantısı
     → 127.0.0.1:3000
     → işletim sistemindeki socket
     → Node process’i
     → request callback’i
     → log dosyasına yazma
     → HTTP response
